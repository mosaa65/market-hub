## الخطوة 1 — طبقة الأمانات الجديدة (قاعدة البيانات)

**الملف المستهدف:** `supabase/migrations/10_milling_and_production.sql` — يُعاد كتابته بالشكل النهائي (R-03).

**يُنشأ:**

1. جدول `custody_ledger` بالأعمدة المعتمدة (`00` §3.1):
   `id, customer_id, warehouse_id, entry_type (INTAKE/MILLING/DELIVERY/ADJUSTMENT), grain_item_id, bags_in/bags_out, kg_in/kg_out, unit_price, amount, service_invoice_id, notes, created_by, created_at`
2. `ENABLE ROW LEVEL SECURITY` + سياسات (قراءة للفريق، كتابة عبر RPC فقط) — R-22.
3. الفهارس: `(customer_id, grain_item_id)`, `(warehouse_id, created_at DESC)`, `(service_invoice_id)`.
4. دوال RPC (SECURITY DEFINER + `search_path = public` + فحص صلاحية داخل الدالة):
   - `custody_intake(customer, warehouse, item, bags, kg, notes)` → سطر INTAKE
   - `custody_milling(customer, warehouse, grain_item, bags_out, kg_out, outputs jsonb)` → سطر صادر حبوب + سطر وارد لكل ناتج، في معاملة واحدة
   - `custody_delivery(customer, warehouse, lines jsonb)` → أسطر DELIVERY (يرفض لو صار الرصيد سالباً)
   - `custody_adjustment(...)` → سطر تعديل جردي مع سبب إلزامي
5. View للقراءة: `custody_balances` = `sum(bags_in − bags_out), sum(kg_in − kg_out)` لكل عميل/صنف/مخزن.

**قواعد داخل الدوال:**

- الكمية الموجبة إلزامية، ورصيد ما بعد العملية ≥ 0 (التسليم لا يسحب أكثر مما عنده).
- `audit_logs` لكل حركة (`stock_impact: 'NONE — customer custody'`).
- لا حقل رصيد مخزَّن إطلاقاً.

**شرط الخروج:** `supabase db reset` ينجح بلا خطأ (R-20).

## الخطوة 2 — طبقة المطابقة (Views)

View واحد يجمع كشف العميل:

- `custody_customer_statement`: لكل عميل/صنف/مخزن — المستلم، المطحون، المسلَّم، **المتبقي** (مشتق، مشتق، مشتق).
- ربط مالي: فواتير الأجور المرتبطة بـ `service_invoice_id` → تبويب «مالي».
- **بند "الفاقد المكتشف"** يظهر هنا فقط: `الوارد − (الناتج + المسلَّم)` للفترة، مع تنبيه إذا تجاوز حداً معقولاً — **تنبيه ولا يمنع** (قرار ق2: يُكتشف لا يُدخل).

## الخطوة 3 — نظافة بيانات الأصناف (Seed)

**المكان:** `supabase/seeds/03_samples/` (بيانات أعمال = ممنوعة في migrations — R-01). عدّل/وسّع `sample-mill.sql`.

- 5–8 أصناف حبوب: `item_class = RAW_MATERIAL` (قمح صلب/بلدي/طري، ذرة، شعير...).
- 4–5 نواتج: `FINISHED_GOOD` / `BY_PRODUCT` (دقيق نمرة 1، دقيق بر، نخالة، سميد).
- صنف خدمي واحد: «أجور طحن وتجهيز» — `item_nature = SERVICE`, `inventory_policy = UNTRACKED`, له **سعر بيع** (مصدر السعر الوحيد).
- مستهلكات: أكياس/خيط/زيت — `NON_STOCK_ITEM` (تُدخل للمستودع وتُصرف — ق4).
- مخزن افتراضي + عميل نقدي.

**شرط الخروج:** إنشاء شركة جديدة + تشغيل الـ seed → كل القوائم في الشاشات الثلاث ممتلئة من القاعدة، لا من مصفوفات الكود.

## الخطوة 4 — الفوترة: فاتورة الأجور (ق5)

- فاتورة `sales_invoices` عادية ببند **واحد**: «أجور طحن وتجهيز»، الكمية = الإجمالي، السعر من المنتج الخدمي.
- الدفع: طرق الدفع القائمة (كتالوج، لا enum مخترع من الواجهة — راجع درس `toStorablePaymentValue` في `unified-operations.ts`).

- كلفة المستهلكات المستخدمة (أكياس مطحنة): تُصرف من المخزون بحركة `STOCK_ISSUE` وتظهر بنداً منفصلاً عند الاقتضاء — لكن أجور الطحن نفسها سطر واحد.

**شرط الخروج:** فاتورة أجور تُصدر وتُسدد وتُرجع بنجاح، والإيراد الخدمي يظهر منفصلاً عن مبيعات المنتجات.
