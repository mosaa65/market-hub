## 1. مقدمة

هذه الوثيقة تصف **الطريقة المبسطة لتشغيل المطحنة** داخل نظام Market-Hub/Vortex ERP. الهدف هو توفير مسار تشغيلي بسيط وعملي يناسب **أغلب المطاحن الصغيرة والمتوسطة** التي لا تحتاج إلى نظام تصنيع معقد بمراحل وأوامر إنتاج.

في هذه الخطة:
- **لا يوجد أوامر إنتاج رسمية** (Production Orders) لبيع الدقيق مباشرة
- **لا يوجد مراحل تصنيع** أو تتبع تفصيلي لعمليات الطحن الذاتي
- **العملية بسيطة:** استقبال ← طحن ← فوترة ← تسليم
- **التركيز على:** المبيعات، المخزون، الإيرادات، المصروفات

هذه الخطة تعمل **بالتوازي** مع خطة التصنيع الموسعة، ولا تلغيها.

## 2. لماذا الخطة المبسطة مناسبة للمطحنة

### مطحنة عادية تعمل بطريقتين:

| النشاط | الوصف | الخطة المناسبة |
|--------|-------|----------------|
| طحن حبوب **العميل** | العميل يُحضر حبوبه، المطحنة تطحنها وتأخذ أجرة فقط | **المبسطة** (الجزء الأماناتي موجود فعلاً) |
| بيع منتجات **المطحنة** | المطحنة تشتري الحبوب وتطحنها وتبيع الدقيق | **المبسطة** (بيع مباشر) أو **التصنيعية** (لتتبع التكلفة) |
| تقديم **خدمات طحن** | أجور الطحن الناعم/الوسط/الخشن | **المبسطة** (فاتورة خدمة) |
| بيع **مواد مساعدة** | أكياس، خيوط، ملصقات | **المبسطة** (بيع عادي من POS) |

### متى تكفي الخطة المبسطة؟

- عندما لا تحتاج المطحنة لتتبع تكلفة الإنتاج بدقة (مادة خام ← منتج جاهز)
- عندما يكون البيع مباشراً بدون أوامر تصنيع
- عندما يكون الطحن لحساب الغير هو النشاط الرئيسي
- عندما تريد نظاماً بسيطاً لا يحتاج تدريباً طويلاً

## 3. الفكرة الجوهرية

### المبدأ الأساسي: فصل مسارين

```
المسار 1: طحن حبوب العميل (أمانات)
═══════════════════════════════════
العميل يُسلّم حبوبه → المطحنة تطحن → المطحنة تُصدر فاتورة أجرة → العميل يستلم الدقيق
• لا يوجد تأثير على مخزون المطحنة (إلا أكياس التعبئة إن كانت من المطحنة)
• الفاتورة = فاتورة خدمة طحن فقط

المسار 2: بيع منتجات المطحنة (تجارة)
═══════════════════════════════════════
المطحنة تملك حبوبًا → تطحنها → تُعبّئ الدقيق → تبيعه مباشرة
• هذا بيع عادي عبر شاشة POS أو المبيعات
• يُخصم من مخزون المنتج الجاهز (دقيق)
• الفاتورة = فاتورة بيع عادية
```

هذا الفصل **موجود فعلاً** في المشروع الحالي ومُوثّق صراحةً في تعليقات الكود:

> ملف `src/lib/milling/index.ts` — السطور 1-17:
> ```
> milling module   grain belongs to a customer, stock impact: NONE
> production       grain belongs to the mill,   stock impact: FULL
> ```

> ملف `src/lib/production/index.ts` — السطور 7-8:
> ```
> milling module   grain belongs to a customer, stock impact: NONE
> this module      grain belongs to the mill,   stock impact: FULL
> ```

## 5. سيناريوهات التشغيل اليومي

### السيناريو 1: بيع دقيق من مخزون المطحنة مباشرة

```
الخطوات:
1. العميل يأتي لشراء دقيق
2. البائع يفتح شاشة POS (/pos) أو المبيعات (/sales)
3. يختار المنتج (مثال: دقيق نمرة 1 — كيس 50 كجم)
4. يحدد الكمية (مثال: 20 كيس)
5. يختار طريقة الدفع (نقد / آجل / تحويل)
6. يحفظ الفاتورة
7. المخزون يتحدث تلقائياً (ينقص 20 كيس)

الأثر:
- فاتورة بيع عادية (sales_invoices)
- حركة مخزون صادرة (stock_movements → movement_type: sale)
- رصيد المنتج ينقص في inventory
- رصيد العميل يتحدث (إن كان آجلاً)
```

**الشاشات المستخدمة:** `_app.pos.tsx` أو `_app.sales.tsx`

---

### السيناريو 2: طحن حبوب العميل (أمانات)

```
الخطوات:
1. العميل يُحضر شاحنة محملة بالقمح
2. يُسجّل سند استلام أمانات (شاشة الاستلام /milling/intake)
   - اسم العميل
   - نوع الحبوب (قمح بلدي، شعير...)
   - عدد الأكياس وسعة الكيس
   - أوزان الميزان (القائم والفارغ → الصافي يُحسب تلقائياً)
   - نسبة الرطوبة والشوائب
   - رقم الشاحنة واسم السائق
   - يُطبع سند الاستلام

3. يُنشأ عقد طحن (اختياري في الخطة المبسطة)
   - نوع الدقيق المطلوب
   - أجرة الكيس أو الطن
   - نسبة الاستخراج المتوقعة
   - مصدر الأكياس (عميل / مطحنة)

4. يُنشأ أمر طحن (شاشة أوامر الطحن /milling/jobs)
   - يرتبط بسند الاستلام
   - الكمية المسحوبة (أكياس × وزن)
   - أجرة الطحن

5. تُسجّل النواتج (دقيق + نخالة + فاقد)
   - لكل ناتج: نوعه، عدد الأكياس، الوزن
   - مصدر الأكياس (عميل أم مطحنة)

6. يكتمل الأمر → يُحسب الفاقد تلقائياً
   - الفاقد = الوزن الداخل − مجموع النواتج
   - يُقارن بالنسبة المسموحة

7. تُصدر فاتورة أجرة الطحن (فاتورة خدمة)
   - أجور الطحن (حسب الأكياس أو الطن)
   - + ثمن أكياس التعبئة (إن كانت من المطحنة)
   - + أجرة الحياكة (اختيارية)

8. يُسلّم العميل ناتجه (شاشة التسليم /milling/delivery)
   - إذن خروج مع تفاصيل الأكياس
   - يُطبع إذن التسليم مع باركود

الأثر:
- لا يتأثر مخزون المطحنة التجاري (الحبوب ملك العميل)
- فقط أكياس التعبئة تُخصم إن كانت من مخزون المطحنة
- فاتورة إيراد خدمة
```

**الشاشات المستخدمة:**
- `_app.milling.intake.tsx` — استلام الأمانات
- `_app.milling.jobs.tsx` — أوامر الطحن
- `_app.milling.delivery.tsx` — التسليم
- `_app.milling.customer-statement.tsx` — كشف حساب الأمانات

---

### السيناريو 3: بيع نخالة أو منتجات جانبية

```
1. المطحنة تملك نخالة (ناتج جانبي من طحن مخزونها الخاص)
2. عميل يريد شراء نخالة
3. تُنشأ فاتورة بيع عادية عبر POS
4. تُخصم من مخزون النخالة
```

### السيناريو 4: شراء حبوب خام

```
1. المطحنة تشتري قمحاً من مورد
2. تُسجّل فاتورة شراء عبر شاشة المشتريات (/purchases)
3. المخزون يزداد (كمية القمح المشترى)
4. رصيد المورد يتحدث
```

**الشاشة:** `_app.purchases.tsx` أو `_app.purchase-pos.tsx`

---

### السيناريو 5: تسجيل مصاريف يومية

```
1. صرف ديزل لمولد المطحنة
2. تُسجّل كمصروف في شاشة المصروفات (/expenses)
3. تُصنّف تحت فئة "وقود ومحروقات"
4. تُحسب في تقارير الأرباح والخسائر
```

## 8. إدارة المخزون

### 8.1 ما يدخل المخزون التجاري

| العملية | التأثير | الجدول |
|---------|---------|--------|
| شراء حبوب من مورد | + زيادة (purchase) | `inventory` + `stock_movements` |
| بيع دقيق من مخزون المطحنة | - نقص (sale) | `inventory` + `stock_movements` |
| بيع نخالة من مخزون المطحنة | - نقص (sale) | `inventory` + `stock_movements` |
| استخدام أكياس لتعبئة طحن الغير | - نقص | `inventory` + `stock_movements` |
| تعديل يدوي (تسوية) | +/- (adjustment) | `inventory` + `stock_movements` |
| تحويل بين مستودعات | +/- (transfer) | `stock_transfers` |
| إرجاع بيع | + زيادة (return_in) | `inventory` + `stock_movements` |
| إرجاع شراء | - نقص (return_out) | `inventory` + `stock_movements` |

### 8.2 ما لا يدخل المخزون التجاري

| العملية | السبب |
|---------|-------|
| استلام حبوب العميل (أمانات) | ملك العميل — في `milling_intake_receipts` فقط |
| نواتج طحن حبوب العميل | ملك العميل — في `milling_job_outputs` فقط |
| تسليم نواتج للعميل | إعادة أمانة — في `milling_delivery_notes` |

> **هذا الفصل مُنفّذ فعلاً** في المشروع. لوحة المطحنة `_app.milling.tsx` تؤكد:
> "هذا الفصل هو ما يحمي تقييم المخزون والوضع الضريبي"

### 8.3 أنواع حركات المخزون الموجودة

من `types.ts` سطر 1435:

```
movement_type: purchase | sale | adjustment | transfer_in | transfer_out
             | return_in | return_out | opening | purchase_return | sale_return
```

| الفئة | أمثلة | نوع المصروف |

## 17. التوصية النهائية للتنفيذ

### الخلاصة

**الخطة المبسطة مُنفّذة بنسبة ~90%** في المشروع الحالي.

### ما يحتاج تنفيذ

| المهمة | الجهد | الوصف |
|--------|-------|-------|
| إضافة صلاحيات `/milling` في `ROUTE_ACCESS` | صغير | إضافة قواعد |
| إعداد فئات مصروفات مخصصة | صغير | بيانات بذرية |
| تقرير يومي مبسط | متوسط | شاشة أو تبويب |
| تنبيهات نقص المخزون | متوسط | وظيفة في لوحة التحكم |

### مبدأ التنفيذ

> **لا حاجة لتعديل أي شيء موجود.** كل المكونات تعمل. المطلوب هو:
> 1. **تكوين البيانات الأساسية** (أصناف، فئات مصروفات، وحدات) عبر البذور
> 2. **إضافة تحسينات طفيفة** في الصلاحيات والتقارير
> 3. **توجيه المستخدم** لاستخدام الشاشات المناسبة لكل عملية

هذه الخطة تعمل **بالتوازي** مع خطة التصنيع. المطحنة التي تحتاج تتبع تكلفة الإنتاج تستخدم شاشة الإنتاج (`/production`) بالإضافة لما سبق.
