# 00 — خطة التبسيط المعتمدة (العقد النهائي)

> **الحالة:** معتمدة من صاحب العمل. هذه الوثيقة **العقد** الذي تُردّ إليه كل قرار لاحق.
> **التاريخ:** 2026-10-12
> **النطاق:** وحدة المطحنة في نظام Market-Hub / Vortex ERP فقط. لا تمسّ باقي الوحدات.
> **قاعدة البيانات:** تجريبية — **إعادة بناء كاملة مسموحة**. لا حاجة لأي migration متسلسل أو توافق خلفي.
> **مرجع ملزم قبل أي تعديل على `supabase/`:** `supabase/MIGRATIONS_RULES.md`.

---

## 0. لماذا وُجدت هذه الوثائق

الوكيل السابق بدأ **التنفيذ مباشرة** قبل أن تُحسم الخطة. والنتيجة:

1. تعقيد تراكمي: أوامر طحن، فاقد، هدر مسموح، صوامع، أوزان عبوات، عقود طحن منفصلة، 4 أوضاع مطحنة، 9 شاشات.
2. جداول ودوال متفرّقة تخدم مفاهيم أعمال **لا تحتاجها مطحنة صغيرة**.
3. الخطة المبسّطة المطلوبة كانت قد كُتبت في تقرير سابق (انظر `txt.txt`) لكن **لم تُعتمد ولم تُنفّذ**.

هذه الوثيقة تُلغي كل ذلك وتضع **القرار النهائي الواحد**. أي وكيل يقرأ هذا الملف يعرف **بالضبط** ما المطلوب، دون الرجوع إلى أي خطة سابقة.

> **قاعدة حاكمة:** الخطط السابقة (أوامر الطحن، الفاقد، الصوامع، الأوضاع الأربعة) **لا وجود لها**. لا تُعدَّل، ولا يُبنى عليها. يُبنى على هذا الملف فقط.

## 1. الفكرة الجوهرية (اقرأها مرتين)

المطحنة نشاط فيه **حاجتان فقط**:

| #       | الحاجة             | الأثر                                               |
| :------ | :----------------- | :-------------------------------------------------- |
| **(أ)** | **خدمة طحن للغير** | العميل يجلب حبوبه → نطحنها → يأخذ ناتجه → نأخذ أجرة |
| **(ب)** | **بيع منتجاتنا**   | نشتري حبوباً أو نطحنها لحسابنا → نبيع دقيق/نخالة    |

**كل ما عدا هذين يدور حولهما** — تخزين، عملاء، ديون، مخزون، حسابات. لا يوجد مسار ثالث.

### المبدأ الحاكم في التصميم

> **جدول واحد، سطر واحد لكل حركة، والرصيد مجموع — لا مخزَّن.**

هذا هو جوهر "الدفتر + الكيس + القلم" التقليدي، لكن منفَّذ في قاعدة بيانات.

**مثال الدورة الكاملة على "كشف العميل" الواحد:**

```
الاستلام   → bags_in += 50        (رصيد العميل صار 50 كيس حبوب)
الطحن      → bags_out += 50 (حبوب) , bags_in += 35 (دقيق) , bags_in += 12 (نخالة)
التسليم    → bags_out += 35 (دقيق) , bags_out += 12 (نخالة)
الرصيد     = مجموع (bags_in − bags_out) لكل صنف = صفر فيزيائياً ✅
المبلغ     = سطر فاتورة أجور واحدة (خدمة)
```

**لا يوجد:** أمر طحن، حالة أمر، إقفال، فاقد، نسبة استخراج، صومعة، وزن عبوة، وحدة خاصة بالطحن.

## 3. نموذج البيانات الجديد (التصميم النهائي)

### 3.1 الجدول الوحيد: `custody_ledger`

جدول واحد يستبدل: `milling_intake_receipts` + `milling_jobs` + `milling_job_outputs` + `milling_delivery_notes` + `milling_delivery_items` + أي جدول رصيد مخزَّن.

| العمود                                | الوصف                                                 |
| :------------------------------------ | :---------------------------------------------------- |
| `id`                                  | المعرّف                                               |
| `customer_id`                         | العميل (من `customers`)                               |
| `warehouse_id`                        | المخزن (من `warehouses`)                              |
| `entry_type`                          | `INTAKE` / `MILLING` / `DELIVERY` / `ADJUSTMENT`      |
| `grain_item_id`                       | الصنف (حبوب خام أو ناتج) من `products` بـ `item_role` |
| `bags_in` / `bags_out`                | الموجب للوارد والسالب للصادر (عدّ الأكياس)            |
| `kg_in` / `kg_out`                    | نفس المبدأ للوزن                                      |
| `unit_price` / `amount`               | السعر والمبلغ (للأجور والتقارير)                      |
| `service_invoice_id`                  | رابط فاتورة الأجور إن وُجدت                           |
| `notes` / `created_by` / `created_at` | —                                                     |

**الرصيد مشتق لا مخزَّن:**

```sql
رصيد العميل = sum(bags_in − bags_out)  لكل صنف ومخزن.
```

أي عملية = سطر واحد يُضاف، ويُعاد حساب الرصيد. **لا sync، ولا حقل يتخلف عن الواقع.**

### 3.2 الأصناف ودورها

الأصناف تُعرَّف في `products` مع دور واضح:

| الدور (`item_class`/`item_role`) | أمثلة                        | سلوكه                                       |
| :------------------------------- | :--------------------------- | :------------------------------------------ |
| `RAW_MATERIAL`                   | قمح صلبة / بلدي / ذرة / شعير | يُطلب عند الاستلام والطحن                   |
| `FINISHED_GOOD` / `BY_PRODUCT`   | دقيق نمرة 1، نخالة، سميد     | يُنتج عند الطحن، يُسلَّم للعميل             |
| `SERVICE`                        | «أجور طحن وتجهيز»            | **لا يُنقص المخزون**، يظهر في فاتورة الأجور |
| `NON_STOCK_ITEM`                 | مستهلكات (أكياس، خيط، زيت)   | تُصرف بفاتورة صرف مستهلكات داخلي            |

> **الأصناف والحبوب والوحدات تُحذف من النماذج كحقول حرة.** لا مصفوفات ثابتة في الكود (`const grainTypes = [...]`). كل اختيار يأتي من قاعدة البيانات.

### 3.3 ما يُحذف من قاعدة البيانات (DROP)

| المحذوف                                                                                                                                                                            | السبب                                  |
| :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------- |
| `milling_jobs` + `milling_job_outputs`                                                                                                                                             | مفهوم "أمر الطحن" ملغى (ق1)            |
| `milling_intake_receipts`                                                                                                                                                          | يُدمج في `custody_ledger`              |
| `milling_delivery_notes` + `milling_delivery_items`                                                                                                                                | يُدمج في `custody_ledger`              |
| `milling_service_agreements`                                                                                                                                                       | شروط الطحن تُحفظ على سطر الاستلام نفسه |
| `milling_grain_grades`                                                                                                                                                             | يُستبدل بـ `item_role` على الأصناف     |
| `milling_unit_conversions`                                                                                                                                                         | لا وحدات خاصة بالطحن (ق3)              |
| `production_boms` + `_bom_lines`                                                                                                                                                   | إنتاج صناعي (ق8)                       |
| `production_orders` + `_materials` + `_outputs` + `_losses`                                                                                                                        | إنتاج صناعي (ق8)                       |
| الأعمدة: `siloid`/`silo_or_location`, `allowed_loss_percentage`, `actual_loss_kg`, `loss_excess_kg`, `expected_extraction_rate`, `nominal_weight_kg`, `moisture_*`, `impurities_*` | فاقد/صوامع/أوزان (ق2, ق3)              |

### 3.4 ما يبقى ولا يُمس (الأصول القائمة)

| العنصر                                                         | لماذا يبقى                                            |
| :------------------------------------------------------------- | :---------------------------------------------------- |
| `products` + `item_class` + `item_nature` + `inventory_policy` | أساس التمييز (خام / نهائي / خدمة / مستهلك)            |
| `warehouses`                                                   | المخزن                                                |
| `customers` + `customer_ledger` + `customer_payments`          | العميل والذم                                          |
| `sales_invoices`                                               | فاتورة الأجور = فاتورة مبيعات عادية تحمل الصنف الخدمي |
| `inventory_movements` + `stock_posting_core`                   | محرك المخزون لبيع منتجاتنا وصرف المستهلكات            |
| `expenses`                                                     | مصروفات التشغيل (كهرباء/ديزل/صيانة)                   |
| `document_numbering` (ترحيل 14)                                | ترقيم المستندات                                       |

## 4. الواجهة النهائية

### 4.1 الشاشات الثلاث (فقط)

| #   | المسار              | الاسم        | ماذا يفعل                                                                                  |
| :-- | :------------------ | :----------- | :----------------------------------------------------------------------------------------- |
| 1   | `/milling/intake`   | **الاستلام** | عميل + صنف حبوب + عدد أكياس + كجم → سطر `INTAKE`                                           |
| 2   | `/milling/milling`  | **الطحن**    | يختار رصيد العميل من الحبوب → يُدخل النواتج (دقيق/نخالة/سميد) بأكياس وكجم → أسطر `MILLING` |

| #   | المسار                        | الاسم                                      |
| :-- | :---------------------------- | :----------------------------------------- |

| الشاشة/المسار                         | القرار                                     |
| :------------------------------------ | :----------------------------------------- |
| `/milling` (لوحة المؤشرات)            | يُدمج في الاستلام — أو يُحذف               |

| `/milling/jobs` (صالة التشغيل)        | **يُحذف**                                  |

| `/milling/operations-guide`           | يبقى كتعليمات                              |
| `/production` (+ كل ما تحته)          | **يُحذف**                                  |
| الوضع `hybrid` / `manufacturing`      | **يُحذف** — يبقى `none` و `simplified` فقط |

### 4.3 زر التصنيع الذكي (بيع منتجاتنا)

لشراء حبوب وطحنها لحسابنا وبيعها: **الاختيار الأبسط** — مستند تحويل واحد:

```
من المخزون → «تحويل/تصنيع»:
  وارد (يُنقص):  1 طن قمح خام   (المخزون ينقص)
  صادر (يزيد):   دقيق 700 كجم + نخالة 300 كجم
  التكلفة: توزيع تكلفة القمح على النواتج حسب أسعار البيع النسبية.
```

> **لماذا لا يكفي "مصروف طحن"?** لأن المصروف لا يُنقص مخزون القمح ولا يُثبّت تكلفة الدقيق، فتظهر تكلفة صفر عند البيع وربح وهمي = خسارة حقيقية.
>
> **لا يُفعل ذلك عبر منظومة الإنتاج الصناعي (BOM/WIP) المحذوفة (ق8).** يُنفَّذ كأبسط صورة للمستند المزدوج: وارد واحد + صادر متعدد + توزيع تكلفة نسبي.

## 5. القواعد الذهبية (تُخالَف = يُرفض العمل)

1. **مصدر واحد للبيانات.** أي قيمة تُدخَل في مكانين ستختلف يوماً ما. الصنف من `products` فقط، السعر من المنتج فقط، المخزن من `warehouses` فقط.
2. **لا رصيد مخزَّن.** الرصيد دائماً `sum(...)`. لا عمود `balance`، لا `sync`.
3. **لا فاقد، لا هدر، لا أوزان عبوات منتجات.** (ق2، ق3)
4. **الكتابة عبر RPC فقط.** الجداول المالية ممنوعة الكتابة المباشرة (R-23).
5. **التعريف النهائي مرة واحدة.** لا `ALTER` متسلسل، لا نفس الكائن مرتين (R-03, R-04, R-13).
6. **لا بيانات أعمال في migrations** — تُنقل إلى `supabase/seeds/` (R-01, R-08).
7. **RLS + `search_path` إلزاميان** (R-22, R-24).
8. **إعادة البناء من الصفر معيار النجاح:** `supabase db reset` ينجح بلا خطأ واحد (R-20).
