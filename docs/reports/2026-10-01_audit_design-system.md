# التقرير الشامل لتدقيق واجهات المستخدم ومنظومة التصميم (Design System Audit) — Market Hub (Vortex ERP)

> **النطاق:** واجهات المستخدم (UI) / تجربة المستخدم (UX) / معمارية الفرونت إند / منظومة التصميم (Design System).  
> **ملاحظة أمان:** لم يتم إجراء أو اقتراح أي تعديل على قاعدة البيانات، عقود الواجهات البرمجية (API Contracts)، منطق الأعمال، أو البيانات المخزنة.

---

## 1. بنية ومكدس الواجهة الحالي (Current UI Stack)

| الطبقة التقنية             | التقنية المستخدمة                                                                                          |
| :------------------------- | :--------------------------------------------------------------------------------------------------------- |
| **محرك التصيير**           | React 19 + Vite 8 + TanStack Start / Router (مسارات قائمة على الملفات)                                     |
| **البيانات والكاش**        | عميل Supabase JS المباشر + TanStack Query                                                                  |
| **التنسيق (Styling)**      | Tailwind CSS v4 (`@import "tailwindcss"` + `@theme inline`)                                                |
| **العناصر الأساسية**       | مكتبة Radix UI Primitives مغلفة بنمط shadcn في `src/components/ui/*` (46 ملفاً)                            |
| **الأيقونات**              | `lucide-react`                                                                                             |
| **إدارة النماذج**          | `react-hook-form` + `zod` (مثبتة ولكن نادراً ما كانت مستخدمة في الصفحات)                                   |
| **الإشعارات المنبثقة**     | `sonner`                                                                                                   |
| **مصادر الحقيقة المركزية** | `src/styles.css` (التوكنز والسمات)، `src/lib/i18n.tsx` (قاموس AR/EN)، `src/lib/format.ts` (`money`, `num`) |

### جرد المسارات التشغيلية (38 مساراً تحت `_app.*`):

- **نظرة عامة (Overview):** `dashboard`, `analytics`, `plans`.
- **العمليات التشغيلية (Operations):** `pos`, `products`, `catalog`, `inventory`, `settlements`, `warehouses`, `batches`, `sales`, `sales-returns`, `purchases`, `purchase-returns`, `transfers`, `barcodes`.
- **العلاقات (Relations):** `customers`, `suppliers`, `loyalty`.
- **المحاسبة والمالية (Accounting):** `payments`, `debts`, `account-statement`, `daily-journal`, `trial-balance`, `income-statement`, `balance-sheet`, `finance`, `reports`.
- **الإدارة (Admin):** `users`, `audit`, `notifications`, `settings`, `platform-admin`.

**الهوية البصرية الحالية:** نمط عصري أنيق ومكثف داكن أولاً (_Linear/Vercel Aesthetic_) باللون الأزرق الكهربائي وتوهج ناعم وألواح زجاجية راقية. هذه الهوية البصرية ممتازة ويجب الحفاظ عليها وتعزيزها بدلاً من استبدالها.

## 2. الأنماط الإيجابية الحالية (يجب الحفاظ عليها)

1. **أساس التوكنز موجود:** يحتوي `src/styles.css` على تسميات دلالية صحيحة للألوان والأسطح والحدود ومقاييس نصف القطر والظلال.
2. **التبديل بين الوضع الداكن والفاتح:** دعم كامل عبر الفئة `.dark` الافتراضية و `.light` مع حفظ التفضيل محلياً.
3. **دعم اللغة العربية و RTL بشكل حقيقي:** عبر `useI18n()` وتطبيق خط `IBM Plex Sans Arabic` واستخدام فئات المحاذاة المنطقية (`start`, `end`, `ms`, `me`, `ps`, `pe`).
4. **فئات الألواح الموحدة (`panel` / `panel-elevated` / `glass`):** تجريد خفيف ومريح مستخدم عبر الشاشات.
5. **لوحة الأوامر السريعة (Command Palette ⌘K):** لمسة احترافية وسريعة موجهة للمحترفين عبر لوحة المفاتيح.
6. **الشريط الجانبي القابل للطي (Icon-rail Sidebar):** يدعم التلميحات السريعة وحفظ الحالة في `localStorage`.
7. **الواجهة متجاوبة مع الصلاحيات والموديولات:** تدعم فحص الأدوار وإظهار الوحدات حسب الباقة المفعلة للمستخدم.

## 3. المشاكل والعيوب المرصودة في الوضع السابق

### 3.1 تكرار المكونات والأنماط (الأعلى خطورة وأثراً)

- **ثلاثة تعريفات مختلفة لثابت `inputCls`:** مكرر في عدة ملفات (`products`, `catalog`, `warehouses`) بتنسيقات مختلفة.
- **تكرار مكون `Field` المحلي:** يُعاد تعريفه في كل صفحة بشكل منفصل.
- **تكرار حقول الإدخال الخام:** أكثر من 6 نسخ لحقول `<input>` طويلة الفئات داخل `pos.tsx` وحدها.
- **15 نافذة منبثقة مكتوبة يدوياً عبر 11 ملف مسار:** كل نافذة لها كود تعتيم وخلفية وظلال وحواف مستقلة.
- **أكثر من 12 شريط بحث مختلف:** بارتفاعات وحواف وسلوكيات متباينة دون توحيد.

### 3.2 تباين وانحراف التوكنز (Token Drift)

- **تشتت نصف القطر (Radius):** 5 مقاييس مختلفة تظهر في نفس الشاشة (`rounded-md`, `rounded-xl`, `rounded-2xl`, `rounded-3xl`, `rounded-full`).
- **تشتت الارتفاعات:** استخدام أزرار وحقول بارتفاع `h-8` و `h-9` و `h-10` و `h-11` دون مقياس منسق.
- **تجاوز ألوان التوكنز:** كتابة ألوان ثابتة ومجردة مثل `emerald-500/10` و `sky-500/10` مما يتسبب في انكسار التباين في الوضع الفاتح.

### 3.3 عيوب التجاوب مع الهواتف الذكية (Responsive Issues)

1. **التعامل مع الجوال كان كفكرة لاحقة:** الاعتماد الشامل على التمرير الأفقي `overflow-x-auto` مما يجبر المستخدم على تمرير الشاشة أفقياً بمقدار 2.5 ضعف عرض الشاشة لرؤية الأعمدة.
2. **النوافذ المنبثقة غير ملائمة للهواتف:** فتح نموذج إضافة منتج يحتوي على 15 حقلاً على شاشة هاتف 360px يجعله يظهر كمربع صغير ومزدحم يصعب التمرير داخله بدلاً من الظهور كدرج سفلي (Bottom Sheet).
3. **غياب الفلاتر على شاشات الجوال:** اختفاء عناصر الفرز والفلترة بالكامل على الهواتف.

### 3.4 مشاكل الجداول وإدارة البيانات

- غياب فرز الأعمدة بالنقر (Click-to-sort).
- غياب الترقيم (Pagination) وجلب البيانات بحد أقصى `.limit(500)` مما يؤدي لثقل المتصفح وظهور رسائل مضللة بأن النتائج مكتملة.
- غياب التوحيد في محاذاة الأرقام والعملات.

## 4. قائمة التوحيد للمكونات المكررة

| المفهوم / المكون                 | عدد مرات التكرار السابقة                               | القرار الهندسي المعتمد                         |
| :------------------------------- | :----------------------------------------------------- | :--------------------------------------------- |
| **حقول النصوص (Text Input)**     | `ui/input.tsx` + 3 تعريفات لـ `inputCls` + نسخ مدمجة   | **توحيد شامل** في مكون `Input` الموحد          |
| **حقول الأرقام والعملات**        | `<input type="number">` خام دون معالجة الأرقام الهندية | **بناء مكوني `NumberInput` و `CurrencyInput`** |
| **تغليف الحقول (FormField)**     | مكونات محلية متفرقة في كل صفحة                         | **توحيد في مكون `FormField`**                  |
| **النوافذ المنبثقة (Modals)**    | 15 نافذة منبثقة مكتوبة يدوياً                          | **توحيد شامل في `Modal` التكيفي**              |
| **رسائل التأكيد (Confirm)**      | استدعاء `window.confirm()` البدائي                     | **استبداله بـ `ConfirmDialog` العصري**         |
| **أشرطة البحث**                  | 12 شريط بحث مختلف                                      | **بناء `SearchInput` الموحد**                  |
| **الجداول**                      | 12 جدول `<table>` خام                                  | **بناء وتطبيق `DataTable` الموحد**             |
| **الترقيم (Pagination)**         | غير موجود في أي صفحة                                   | **إضافة نظام ترقيم تلقائي متقدم**              |
| **شارات الحالة (Status Badges)** | 8 أشكال مختلفة من الشارات                              | **استخراج مكون `StatusBadge` الموحد**          |

## 5. منظومة التصميم الموصى بها (المعمارية ثلاثية الطبقات)

```text
Layer 0: Tokens       → src/styles.css · src/design/tokens.ts
Layer 1: Primitives   → src/components/ui/* (Button, Input, Modal, DataTable...)
Layer 2: Patterns     → src/components/vortex-ui/* (TableToolbar, FormGrid, FormField, FormSection)
Layer 3: Pages        → src/routes/_app.*.tsx (منطق البيانات والترجمة فقط)
```

### القواعد الهندسية المركزية:

- استقاء كافة القيم البصرية من متغيرات CSS المعرفة في ثيم Tailwind.
- تولي الطبقة الثانية (Layer 2) مسؤولية تركيب العناصر (التسمية + الحقل + التلميح + الخطأ؛ الجدول + شريط الأدوات + الحالة الفارغة + الترقيم).
- بقاء الصفحات مسؤولة فقط عن جلب البيانات وعرضها، ومنع كتابة سلاسل فئات Tailwind الطويلة داخل الصفحات.
