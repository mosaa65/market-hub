## 0. نظرة عامة في سطر واحد

كل نسخة احتياطية هي **ملف JSON مشفّر (AES-256-GCM)** بامتداد `.vortexbak`، حمولته إفراغ خادمي ديناميكي لكل جداول public، وتُكتب في 3 وجهات قابلة للتكوين: التنزيل للمتصفح، حاوية Supabase Storage (`tenant-backups`)، ومسارات محلية مخصصة على القرص — وكل ذلك يعمل **بنفس الكود** على الدوكر المحلي والسحابة.

## 2. كيف يعمل في البيئة **المحلية** (Docker)

### 2.1 التهيئة (مرة واحدة)

```powershell
supabase start                        # يشغّل حاويات الدوكر (db, auth, storage, ...)
supabase db push                      # يطبّق Migration 31 (دوال الخادم الثلاث)
supabase storage buckets create tenant-backups   # أو من dashboard المحلي :54323
```

### 2.2 آلية النسخ خطوة بخطوة

1. المالك (أو المدير) ينقر "تنزيل نسخة" في شاشة الإعدادات.
2. المتصفح يستدعي `supabase.rpc('backup_export_all')` — الاتصال ذاهب إلى Postgres **داخل حاوية الدوكر**.
3. الدالة تتجاوز RLS (`SECURITY DEFINER`) بعد فحص دور `owner/manager`، وتقرأ **كل جداول public من `information_schema` وقت النسخ** — أي جدول تضيفه بأي مهاجرة جديدة يدخل تلقائياً بلا تعديل كود. جداول السجل الضخمة (`audit_logs`, `backup_logs`, `idempotency_keys`) تُفرَّغ بأحدث 5000 صف فقط.
4. الدالة تحسب **بصمة السكيما** (SHA-256 لكل الجداول + الأعمدة + أنواعها) وتضمّنها في الحمولة.
5. الحمولة تُشفَّر **في المتصفح** بـ AES-256-GCM ثم تُكتب كملف `.vortexbak`.

### 2.3 الوجهات الثلاث في المحلي

| الوجهة              | إلى أين تذهب النسخة فعلياً                                                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **تنزيل محلي**      | مجلد Downloads بالمتصفح (دائماً)                                                                                                                                |
| **سحابي (Storage)** | حاوية `tenant-backups` داخل **Storage في حاوية الدوكر نفسها** — نفس الكود `supabase.storage.from('tenant-backups').upload()` يتصل بالنقطة المحلية، بلا أي تعديل |
| **مسارات مخصصة**    | أي مجلد/قرص اختاره المستخدم سابقاً (`D:\Backups`, USB…) — كتابة مباشرة عبر File System Access API                                                               |

### 2.4 سكريبت `pg_dump` الإضافي (نسخة على مستوى الملفات)

`scripts/local_backup.ps1` يأخذ نسخة SQL خام كاملة (سكيما + بيانات + RLS + sequences) مباشرة من حاوية الدوكر عبر `pg_dump`، مع تدوير تلقائي (آخر 20 نسخة) وإمكانية نسخ لعدة مسارات:

```powershell
.\scripts\local_backup.ps1                          # نسخة إلى backups/
.\scripts\local_backup.ps1 -CopyTo "D:\Backups","E:\"  # + مسارات إضافية
```

**الفرق الجوهري:** نسخة `.vortexbak` تعمل من المتصفح في أي بيئة (تُستعادة بأي متصفح)، بينما نسخة `pg_dump` ملف SQL خام يُستعاد بـ `psql` — الأفضل الاحتفاظ بالنوعين.

### 2.5 الاستعادة في المحلي

1. المالك يرفع ملف `.vortexbak` في نافذة "الاستعادة".
2. يُدخل كلمة مرور التشفير → `validateBackupFile()` يفك التشفير ويتحقق من التوقيع (AES-GCM Auth Tag) وبنية الحمولة.
3. زر **"تأكيد وتنفيذ الاستعادة الفعلية (الخادم)"** يستدعي `restoreTenantDataServerSide(payload)` → RPC `backup_restore_all` ينفّذ داخل **Transaction واحد**: تعطيل المفاتيح الخارجية مؤقتاً → `TRUNCATE` لكل جداول public → إدراج بالاسم (يتكيف مع ترتيب الأعمدة الجديد) → إعادة ضبط sequences. أي فشل في أي خطوة = **ROLLBACK كامل، لا يُمسّ شيء**.

## 3. كيف يعمل في البيئة **السحابية**

**لا يوجد أي اختلاف في الكود** — فقط نقطة الاتصال:

| الجانب              | الدوكر المحلي                                                | السحابة                                                                |
| ------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| مصدر `SUPABASE_URL` | `127.0.0.1` / منفذ محلي من config.toml                       | `https://xxx.supabase.co`                                              |
| قاعدة البيانات      | Postgres داخل حاوية دوكر                                     | Postgres سحابي مُدار                                                   |
| Supabase Storage    | خادم storage داخل حاوية دوكر (`tenant-backups` محلية)        | Storage سحابي (`tenant-backups` سحابية)                                |
| دوال النسخ (RPC)    | تعمل كما هي — Migration 31 تُطبَّق بـ `db push` على أي منهما | تعمل كما هي                                                            |
| التشفير             | في المتصفح (AES-256-GCM) — لا يتأثر بالبيئة                  | في المتصفح                                                             |
| ملاحظة مدفوعات      | كل شيء مجاني                                                 | الخطة المجانية تكتفي؛ **PITR/Daily Backups مدفوعة ولا نستخدمها أصلاً** |

المستخدم الذي يعمل على نسخة محلية يومياً ويستخدم "سحابي فقط (Supabase Storage)" يحصل فعلياً على نسخ داخل الدوكر — وهذا هو المقصود بملاحظتك: **"سحابي" هنا يعني Storage البيئة المتصلة، مهما كانت محلية أو سحابية.** الانتقال للإنتاج السحابي لا يتطلب تغيير سطر واحد؛ فقط غيّر مفاتيح الاتصال وطبّق المهاجرات وأنشئ الحاوية هناك.

## 4. المسارات المخصصة على الجهاز (ميزة v3.1)

### كيف أفعّلها؟

في شاشة الإعدادات ← قسم **"مسارات نسخ مخصصة على الجهاز"** ← "إضافة مسار" ← تظهر نافذة نظامية لاختيار مجلد من أي قرص. أضف ما شئت (قرص D، USB، مجلد شبكة محوَّل…) — كل مسار يُسجَّل ويظهر في القائمة مع زر حذف.

### التقنية المستخدمة

- **File System Access API** (`showDirectoryPicker`): المتصفح لا يستطيع الكتابة في أي مسار إلا بذاتية المستخدم عبر نافذة نظامية — آمن بتصميمه.
- مقابض المجلدات (Directory Handles) تُخزَّن في **IndexedDB** (`vortex_backup_dir_handles`) والقائمة المسماة في localStorage.
- عند كل نسخة (يدوية أو مجدولة): `writeBackupToCustomDirs()` تكتب الملف المشفّر في كل المسارات تلقائياً، مع طلب إذن الوصول تلقائياً إن انتهت الجلسة.

### القيود المعلنة

- يعمل على **Chrome/Edge فقط** (Firefox لا يدعم الـ API) — على المتصفحات الأخرى القسم يختفي من الواجهة تلقائياً ويبقى التنزيل العادي.
- قد يطلب المتصفح إعادة السماح بالوصول عند أول نسخة بعد إعادة فتح النظام (نقرة واحدة).
- أفضل تجربة مع تثبيت النظام كتطبيق PWA.

## 5. الجدولة التلقائية والوجهات مجتمعة

إعداد "مكان التخزين المفضل" (`destination`) يتحكم في توزيع كل نسخة:

| الإعداد | التنزيل للمتصفح | Supabase Storage | المسارات المخصصة      |
| ------- | --------------- | ---------------- | --------------------- |
| `local` | ✅              | ❌               | ✅ (دائماً عند الدعم) |
| `cloud` | ✅              | ✅               | ✅                    |
| `both`  | ✅              | ✅               | ✅                    |

الجدولة (`reminder_frequency`: مرتين يومياً / يومياً / أسبوعياً) تُدير تذكير التنزيل عبر `reminder.ts`، وكل حركة تُسجَّل في جدول `backup_logs` مع نوع التخزين الفعلي المستخدم وحجم الملف وأي أخطاء (فشل رفع سحابي، مسار مرفوض…).

## 6. الحماية والصلاحيات (موجزة)

| الطبقة              | الآلية                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| من يستطيع النسخ     | دور `owner` أو `manager` — فحص داخل الدالة الخادمية نفسها (`SECURITY DEFINER`)                                           |
| من يستطيع الاستعادة | دور `owner` **فقط**                                                                                                      |
| سرية المحتوى        | AES-256-GCM بمفتاح لا يعرفه الخادم — حتى لو سُربت قاعدة البيانات أو Storage تبقى النسخ غير قابلة للقراءة دون كلمة المرور |
| سلامة الملف         | Auth Tag + SHA-256 checksum — أي تلاعب يُكتشف عند الفحص                                                                  |
| انحراف السكيما      | بصمة SHA-256 مدمجة في النسخة؛ اختلافها عند الاستعادة يظهر تنبيهاً (وليس إيقافاً)                                         |
| ذرية الاستعادة      | Transaction واحد — إما نجاح كامل أو ROLLBACK كامل                                                                        |
