# 1. نظرة عامة على المشروع (Project Overview)

- **اسم المشروع:** Vortex ERP (Market Hub)
- **نوع المشروع:** تطبيق ويب متكامل لإدارة الموارد المؤسسية (Web-based ERP Application).
- **مجال الأعمال (Business Domain):** تجارة التجزئة، الجملة، ومحلات السوبرماركت والمواد الغذائية والقرطاسية.
- **الهدف الأساسي:** توحيد عمليات نقاط البيع (POS)، المشتريات، المخزون، المستودعات، الإدارة المالية، سجلات العملاء والموردين، والتقارير الرقابية والتحليلية في منصة مركزية واحدة.
- **المستخدمون المستهدفون:** الكاشير، موظفو المستودعات، المحاسبون، المديرون، وأصحاب الأعمال.
- **القيمة التشغيلية المضافة:** ربط الحركات التشغيلية اليومية بضبط المخزون، القيود المحاسبية، والتقارير الرقابية مع حماية دقيقة للبيانات قائمة على الأدوار والصلاحيات (Role-Aware Access).

---

# 2. ملخص السيرة المهنية والإنجازات الفنية (Resume Summary)

- بناء وتطوير منصة ERP متكاملة باستخدام TypeScript و React لتجارة التجزئة والجملة بالاعتماد على TanStack Start، و Supabase، وقاعدة بيانات PostgreSQL.
- هندسة وتطبيق تدفقات المعاملات الآمنة والذرية (Transactional Workflows) لعمليات المبيعات، المشتريات، المرتجعات، التحويلات المخزنية، مدفوعات العملاء، ونقاط الولاء باستخدام دوال PostgreSQL RPC.
- تصميم وتنفيذ نموذج وصول آمن مقيد بالأدوار بالاعتماد على Supabase Auth وسياسات أمان مستوى الصفوف (Row Level Security - RLS) ودوال فحص الصلاحيات البرمجية على مستوى قاعدة البيانات.
- تقديم واجهات تشغيلية احترافية ثنائية اللغة (عربي/إنجليزي) تدعم الاتجاهين RTL و LTR، مع لوحات تحليلات متقدمة، طباعة فواتير حرارية و A4، تصدير CSV، مسح وتوليد الباركود، وتجاوب كامل مع مختلف الشاشات.

# 3. الميزات والوحدات الرئيسية (Core Features)

- **نقاط البيع والمبيعات (POS & Sales):** واجهة مبيعات فورية وسريعة، إدارة طرق الدفع المتعددة، طباعة الفواتير الحرارية والـ PDF الفاخر، ودعم أجهزة الباركود.
- **المخزون والمنتجات (Inventory & Products):** إدارة دليل المنتجات، أكواد SKU والباركود، جرد المخزون، التسويات المخزنية، سجل حركات الأصناف، إدارة الدفعات (Batches)، وتتبع تواريخ الصلاحية والتحويلات بين المستودعات.
- **المشتريات والعلاقات (Purchases & Relations):** إدارة المشتريات، مرتجعات المبيعات والمشتريات، أرصدة وكشوفات الموردين، أرصدة العملاء، تحصيل المدفوعات، وبرامج الولاء.
- **المالية والتقارير (Finance & Reporting):** لوحات معلومات وإحصائيات تفاعلية، تقارير تشغيلية ومالية، سجل تدقيق العمليات (Audit Logs)، الإشعارات وإدارة المستخدمين.
- **تجربة المستخدم والتعريب (UX & Localization):** دعم أصيل ومحكم للغة العربية و RTL، التبديل السلس بين اللغات، حفظ المظهر (داكن/فاتح)، والتنقل السلس عبر الهواتف والأجهزة اللوحية.

# 5. التحليل المعماري للنظام (Architecture Analysis)

يعتمد نظام Vortex ERP نمط **المونوليث الموحد والمنظم (Modular Monolith)**:

- مسارات TanStack Start المبنية على الملفات (`src/routes`) تفصل بين الشاشات والنطاقات التشغيلية (POS، المخزون، المشتريات، المبيعات، المالية، والتحليلات).
- المكونات المشتركة (`src/components`) تحتوي على إطار التطبيق الأساسي (App Shell)، وشريط التنقل، وقارئ الباركود، ولوحة الأوامر السريعة (Command Palette ⌘K)، والعناصر الأساسية للواجهة.
- طبقة الخدمات المشتركة (`src/lib`) تجمع منطق المصادقة، والتعريب، وتنسيق الأرقام والعملات، وقوالب الطباعة، ومعالجة الأخطاء.
- مجلد التكامل (`src/integrations/supabase`) يعزل عميل Supabase المطبوع بأنواعه (Typed Client)، وعمليات إدارة الخادم، ودوال التحقق من الجلسات.
- تتولى قاعدة بيانات PostgreSQL العمليات المالية والتنفيذية الحساسة عبر دوال RPC لضمان المعاملات الذرية (ACID Transactions)، وتفرض حماية البيانات عبر سياسات RLS.

# 6. ممارسات هندسة البرمجيات (Software Engineering Practices)

- **التصميم المعياري (Modular Design):** عزل متطلبات كل نطاق عمل في مسارات ومكونات مستقلة لتقليل الاعتماديات المتشابكة.
- **المكونات القابلة لإعادة الاستخدام (Reusable Components):** توحيد الجداول (`DataTable`)، والنوافذ المنبثقة، وحقول الإدخال، وأشرطة البحث عبر طبقات منظومة التصميم.
- **مبدأ DRY (Don't Repeat Yourself):** توحيد دوال التنسيق المالي والتواريخ والترجمة والاتصال بالبيانات في دوال مركزية.
- **التحقق الصارم من المدخلات (Validation):** فحص مدخلات المصادقة عبر مخططات Zod، وفحص العمليات المالية وصلاحيات المخزون داخل دوال PostgreSQL RPC.
- **معالجة الأخطاء (Error Handling):** ترجمة أخطاء قاعدة البيانات والمصادقة إلى رسائل مفهومة للمستخدم النهائي، وحماية واجهة المستخدم من الانهيار باستخدام Error Boundaries.
- **إدارة الإعدادات والبيئة (Configuration Management):** حماية المفاتيح الحساسة في المتغيرات البيئية (`.env`) وعزل مفتاح `SERVICE_ROLE_KEY` في بيئة الخادم فقط.

# 7. معمارية قاعدة البيانات (Database Architecture)

- **المحرك:** PostgreSQL مستضاف عبر منصة Supabase السحابية.
- **الهيكلة:** فصل واضح بين بيانات الهوية، البيانات المرجعية للفهرس (Master Catalog)، المخزون، الفواتير وبنودها، الحركات المالية، سجلات الولاء، وسجل التدقيق الشامل.
- **العلاقات والتكاملية (Integrity):** مفاتيح أجنبية (Foreign Keys)، قيود فريدة (Unique Constraints) لأكواد SKU والباركود والدفعات، وقيود فحص رقمية (Check Constraints) تمنع الأرصدة والكميات غير المنطقية، ومحفزات Triggers لتحديث حقل `updated_at` تلقائياً.
- **الترحيلات (Migrations):** تتبع منظم ومؤرخ لترحيلات SQL في المجلد `supabase/migrations`.
- **الفهارس (Indexes):** فهارس بحث نصوص متقدمة (GIN Indexes) للبحث الفوري في المنتجات، وفهارس لتسريع استعلامات تواريخ انتهاء الدفعات وسجلات التدقيق وحركات المخزون.

# 8. تحليل الأمان والصلاحيات (Security Analysis)

- **المصادقة (Authentication):** إدارة الحسابات والجلسات وتجديد التوكنات عبر Supabase Auth.
- **التحكم بالوصول المبني على الأدوار (RBAC):** تحديد أدوار تشغيلية واضحة في النظام: المالك (`owner`)، المدير (`manager`)، المحاسب (`accountant`)، الكاشير (`cashier`)، ومسؤول المستودع (`warehouse`).
- **حماية مستوى الصفوف (Row Level Security - RLS):** تطبيق سياسات RLS صارمة على جميع الجداول التشغيلية مع دوال أمان مثل `has_role` و `is_staff`.
- **أمان العمليات الحساسة (Transactional Hardening):** التحقق من هوية المستخدم `auth.uid()` وأدواره داخل دوال RPC المحمية، وإلغاء صلاحيات الوصول العام (`PUBLIC/anon`) عن الدوال الإدارية.
- **حماية المسارات:** إعادة توجيه المستخدمين غير المصادق عليهم تلقائياً من المسارات المحمية إلى صفحة تسجيل الدخول (`/auth`).

# 9. التكامل والواجهات البرمجية (API & Integrations)

- **نمط التكامل:** لا يعتمد النظام على واجهات REST تقليدية مكتوبة يدوياً، بل يتصل بقاعدة البيانات عبر عميل Supabase المباشر والمحمي بسياسات RLS، ودوال PostgreSQL RPC للمعاملات الذرية.
- **تغطية عمليات RPC:** إنشاء المبيعات، المشتريات، المرتجعات، التحويلات المخزنية، تسديد الدفعات، وتعديل نقاط الولاء.
- **الاستجابة والأخطاء:** تُرجع دوال الخادم أخطاء واضحة في حال نقص الكميات أو تجاوز حدود الائتمان أو نقص الصلاحية، لتعرضها الواجهة برسائل توضيحية.
