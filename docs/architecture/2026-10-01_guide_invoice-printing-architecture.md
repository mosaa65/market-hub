# معمارية وتوثيق محرك طباعة الفواتير والمستندات (Invoice & Printing Architecture)

> **المشروع:** Vortex ERP (Market Hub)  
> **نطاق الوحدة:** الفوترة، معالجة المستندات، محرك الطباعة، وسجل القوالب (Template Registry)  
> **حالة قاعدة البيانات:** صفر تغيير على مخطط قاعدة البيانات أو الجداول (Zero Database Mutations - يعتمد بالكامل على المتصفح وتخزين LocalStorage).

---

## 1. نظرة عامة على المعمارية الهندسية

تم تصميم نظام الطباعة في Vortex ERP مع التزام صارم بمبدأ **فصل الاهتمامات (Separation of Concerns)** ليدعم مستقبلاً أكثر من 50 قالباً مخصصاً وعدة أنواع مختلفة من المستندات بسلاسة وكفاءة.

```text
┌─────────────────────────────────────────────────────────┐
│        حدث تشغيلي (عملية بيع POS / شراء / تحويل مخزني)   │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│     نموذج بيانات المستند الموحد (UnifiedDocumentData)   │
│  - نوع وبيانات المستند الوصفية (docType)                │
│  - البنود، الكميات، الوحدات، وأكواد الباركود            │
│  - البيانات المالية (الإجمالي قبل الضريبة، الخصم، الصافي) │
│  - بيانات الحركة (المستودع، الكاشير، المرجع)            │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│    سجل القوالب ومحرك تصيير المستندات (Renderer Engine)   │
│  - registerTemplate(meta, renderer)                     │
│  - getTemplateRenderer(id, docType)                     │
│  - renderDocumentHTML(doc, templateId, labels, options) │
└───────────────────────────┬─────────────────────────────┘
                            │
            ┌───────────────┴───────────────┐
            ▼                               ▼
┌──────────────────────┐        ┌────────────────────────┐
│    فاتورة العميل     │        │    مستندات المخزون     │
│ (حرارية / A4 / فاخرة) │        │ (سند صرف / تحويل مخزني) │
└──────────────────────┘        └────────────────────────┘
```

## 2. نموذج البيانات الموحد للمستندات (`UnifiedDocumentData`)

لتجنب ربط القوالب مباشرة بجداول قاعدة البيانات مثل `sales_invoices` أو `purchase_invoices`، يتم تحويل جميع البيانات أولاً إلى نموذج موحد:

- **نوع المستند (`docType`):**
  - `sale`: فاتورة مبيعات.
  - `purchase`: فاتورة مشتريات.
  - `sale_return`: إشعار دائن / مرتجع مبيعات.
  - `purchase_return`: مرتجع مشتريات.
  - `stock_transfer`: سند تحويل بين مستودعين.
  - `stock_issue`: سند صرف مخزني.
  - `receipt`: إيصال استلام أو دفع مالي.

- **بنية البنود (`items`):**
  - `name`: اسم الصنف (عربي/إنجليزي).
  - `barcode`: كود الباركود للصنف.
  - `quantity`: الكمية المباعة أو المحولة.
  - `unitPrice`: سعر الوحدة.
  - `discount`: قيمة الخصم الممنوح على البند.
  - `tax`: قيمة الضريبة.
  - `total`: الإجمالي النهائي للبند.

- **المعلومات المالية الشاملة (`financials`):**
  - الإجمالي الفرعي، إجمالي الخصومات، إجمالي الضرائب، والمبلغ النهائي الصافي.
  - المبلغ المدفوع والمتبقي (في فواتير الآجل أو السداد الجزئي).
  - **التفقيط المالي التلقائي:** تحويل المبالغ كتابةً باللغة العربية الفصحى (مثل: _فقط خمسة آلاف ريال يمني لا غير_).

## 3. سجل القوالب ومحرك التصيير (`Template Registry`)

كل قالب هو عبارة عن دالة تصيير مستقلة (`Renderer Function`) تنتج كود HTML/CSS نظيفاً ومتجاوباً للطباعة دون الاعتماد على مكتبات خارجية بطيئة:

### القوالب المعتمدة في النظام:

1. **القالب الحراري (Thermal ESC/POS):**
   - العرض: 80 مم أو 58 مم.
   - مخصص لطابعات الإيصالات السريعة في نقاط البيع والكاشير.
   - يتضمن باركود الفاتورة وشعار المتجر المصغر وتفاصيل الحساب.

2. **القالب القياسي (Standard Blue A4):**
   - تخطيط A4 كلاسيكي ومريح للعين مع ترويسة زرقاء أنيقة.
   - جداول واضحة وتفقيط للمبلغ ومساحة للملاحظات وتوقيعات الاستلام.

3. **القالب الفاخر (Luxury Gold A4):**
   - تصميم مؤسسي راقٍ بتدرجات ذهبية ومربعات إجماليات مميزة.
   - بطاقات بيانات ثلاثية للعناوين وشعار المتجر بدقة عالية.

4. **قالب سندات المخزون (Inventory Slip):**
   - مخصص لعمليات التحويل بين المستودعات وسندات الإخراج والصرف المخزني.
   - يركز على رقم المستودع المصدر والمستقبل، أسماء السائقين أو المستلمين، وأرقام التشغيلات (Batches).

---

## 4. نظام الطباعة وتكامل الطابعات (Print Service)

يدعم النظام وسيلتين للطباعة:

1. **الطباعة المباشرة عبر المتصفح (Browser Print Flow):**
   - يتم توليد كود HTML وتمريره إلى نافذة أو `iframe` معزول لحمايته من ستايلات الصفحة.
   - استدعاء أمر `window.print()` مع تطبيق قواعد `@media print` الصارمة لإخفاء هوامش المتصفح وضمان جودة الخطوط.

2. **توليد وتصدير PDF:**
   - استخدام طباعة المتصفح إلى PDF المدمجة لحفظ جودة الخطوط العربية بدقة `Vector` ودعم الشعار والألوان.
   - توفير خيار الحفظ الفوري للمستند باسم منسق (مثل: `INV-2026-0001.pdf`).

---

## 5. ميزات الأمان وسلامة البيانات

- **عزل تام عن قاعدة البيانات:** محرك الطباعة يعمل بالكامل على مستوى العميل (Client-Side)، ولا يقوم بأي استعلام تعديل أو حذف.
- **الحماية من انكسار الصور والشعار (Smart Logo Fallback):** في حال عدم توفر رابط شعار صالح للشركة في الإعدادات، يتم الرجوع تلقائياً إلى الشعار الافتراضي للنظام بدون إظهار أيقونة صورة تالفة عبر معالج `onerror`.
- **توافق كامل مع RTL:** جميع القوالب مصممة بنمط `dir="rtl"` كمعيار أساسي ومختبرة لضمان محاذاة الأرقام والجداول والعملات بالشكل الصحيح.
