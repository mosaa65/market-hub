## 0️⃣ الفلسفة الصحيحة للنظام (الأساس الذي يجب أن تحكمه كل القرارات)

النظام **ليس نظام تصنيع كامل (MRP/Manufacturing)**. هو نظام **تجاري مبسط** يعتمد على ثلاث عمليات فقط:

| النوع | التعريف | مثال | التأثير المحاسبي |
|---|---|
| **خدمة (Service)** | نشاط نحقق منه إيراد أجور، المادة خامُ عميل لا تملكها المنشأة | طحن حبوب العميل | إيراد خدمة فقط + أمانة خارج المخزون |
| **تحويل (Conversion)** | نقل مخزون من شكل إلى آخر **داخل المنشأة** بنفس التكلفة تقريباً | قمح مخزون → دقيق + نخالة | حركة بين أصناف، لا إيراد ولا تكلفة إنتاج موزعة |
| **بيع/شراء (Trade)** | تدوير تجاري عادي | شراء قمح، بيع دقيق | فواتير عادية بتكلفة طبقات المخزون |

**قاعدة ذهبية:** لا «توزيع تكلفة نسبي»، لا «أوامر إنتاج»، لا «مركز تكلفة تصنيعي».
المصروفات (أجور، مستلزمات، غاز، مشغّل) = **سندات مصروفات عادية** في دفتر المصروفات.

# القسم الأول: خدمة طحن الغير (Amanah Milling) — الدورة الكاملة

## 1.1 المبدأ المحاسبي والمالي

```
حبوب العميل = ملك العميل = أمانة
            ║ لا تدخل مخزون الشركة إطلاقاً
            ║ لا تظهر في تكلفة أي شيء
            ║ لا تُقيّم ولا تُسعّر
الإيراد الوحيد = أجور الطحن (فاتورة خدمة)
```

- المخزون «الشركي» (owner_type = COMPANY) لا علاقة له بالحبوب المستلمة للطحن.
- الحبوب والنواتج تُتتبع في **جداول أمانات منفصلة** مرتبطة بالعميل، أو كحركات مخزون
  بـ `owner_type = CUSTOMER` و `owner_id = العميل` — وهي الطريقة الحالية الصحيحة
  (المحرك `post_stock_delta` يدعم owner منفصل، والحجب `v_after < 0 AND p_owner_type='COMPANY'`).
- النواتج (دقيق/نخالة) **تبقى ملك العميل** من لحظة الطحن حتى تسليمها له.
  **لا تسعير تلقائي ولا حساب تكلفة للنواتج من عملية الطحن** — هذا لم يكن ويستحيل أن يكون
  عملية إنتاج، بل **عملية تحويل ملكية الشكل داخل أمانة العميل**.

## 1.2 بيانات أنواع الحبوب (Grain Types)

المطلوب أن تكون البيانات المرجعية للحبوب مستقلة وواضحة:

| الحقل | الغرض | مثال |
|---|---|---|
| `grain_type_id` | معرف | قمح بُرّ / قمح أسمر / ذرة / شعير |
| `name_ar / name_en` | الاسم | قمح بُرّ |
| `default_loss_rate_pct` | نسبة الفاقد الافتراضية | 2% |
| `default_output_map` | النواتج الافتراضية | دقيق 78%، نخالة 20% |
| `is_active` | التفعيل | ✅ |

**الخطأ الحالي:** الحبوب تُختار من كتالوج المنتجات العادي (`fetchGrainItems` تبحث في
`products` بشرط `item_nature`)، فتختلط الحبوب المرجعية بأصناف الشراء الحقيقية،
ولا يوجد جدول أنواع حبوب بفاقد افتراضي ونسب نواتج — الفاقد يُدخل يدوياً فقط في كل عملية.

**البناء الصحيح:** جدول `grain_types` مستقل + ربط عملية الطحن به، مع إمكانية
استخدام النسب الافتراضية ثم تعديلها لكل عملية يدوياً (بسبب طبيعة كل طرقة حجر).

## 1.3 دورة عملية الطحن الكاملة (من البداية إلى النهاية)

### الخطوة 1 — الاستلام (Intake)
| العنصر | التفصيل |
|---|---|
| المستند | «سند استلام أمانة» برقم متسلسل خاص بالطحن |
| البيانات | العميل (إلزامي)، نوع الحبوب، الوزن بالكجم، عدد الأكياس المتوقعة، ملاحظات |
| الحركة | `post_stock_delta` بـ `owner_type=CUSTOMER, owner_id=العميل` — **حركة استلام أمانة** |
| المخزون الشركي | **لا يتغير** ✅ (هذا صحيح في النظام الحالي ويجب الحفاظ عليه) |
| الطباعة | سند استلام يعطى للعميل (ثبوت بالوزن) |

### الخطوة 2 — الطحن (Milling)
| العنصر | التفصيل الصحيح |
|---|---|
| طبيعة العملية | **تحويل داخل الأمانة**: حبوب أمانة (كجم) → نواتج أمانة (كجم) |
| المعادلة | `وزن الحبوب المستهلك = مجموع النواتج + الفاقد` (موجودة حالياً ✅) |
| الفاقد | افتراضي من نوع الحبة + تعديل يدوي، ويظهر كفرق موثق |
| النواتج | أدخلها **بالوزن الكجم أولاً**، ثم *ربطها بأكياس التعبئة اختيارياً* — النواتج أمانة، والأكياس فقط لصفة التسليم |
| **الخطأ القاتل الحالي** | النظام الحالي يعامل النواتج كأصناف شركية بأسعار بيع ويحسب لها قيمة سوقية (إجمالي القيمة السوقية للنواتج في `milling.milling.tsx`) — **هذا غير صحيح**: قيمة السوق بلا معنى لممتلكات العميل |

### الخطوة 3 — الفاتورة (أجور الطحن)
| العنصر | التفصيل |
|---|---|
| طبيعتها | **فاتورة خدمة** (صنف خدمة واحد: «أجور طحن») على العميل |
| الأساس | التسعير التعاقدي **المتّفق عليه في البداية** وفق أساس مسجّل: `PER_BAG` (لكيس مُطحَن) أو `PER_KG` (لكيلو مُطحَن). الأكياس المُطحَنة (الاستلام) هي أساس الحساب — **لا علاقة له بعدد الأكياس الناتجة بعد الطحن**، فالناتج ملك العميل ولا يحاسب عليه |
| التوقيت | **الاستلام والفاتورة في نفس العملية والمستند الواحد** (`milling_service_documents` بحالة `RECEIVED` → فاتورة صادرة فوراً) — هذا التصميم سليم عمداً لأن الاتفاق يجري في البداية؛ لا فواتير لاحقة ولا مفاجآت بعد الطحن |
| ما تُرحَّل | إيراد خدمة + ذم/صندوق/بنك — **لا COGS** (لا توجد كلفة بضاعة) |
| الحالات | `RECEIVED` (استُلم و فوترة) → `PROCESSED` (طُحن) → `DELIVERED` (سُلّم) |
| **تصحيح للتقرير السابق** | ملاحظة «الفاتورة تُصدر قبل معرفة الأكياس الناتجة» كانت خطأً في فهمنا — التسعير ليس على الناتج أصلاً، بل على الكمية المُطحَنة المتفق عليها، والإصدار الفوري مقصود |

### الخطوة 4 — التسليم (Delivery)
| العنصر | التفصيل |
|---|---|
| طبيعة العملية | تسليم نواتج الأمانة للعميل (كيل/حصّة) |
| الرصيد | بطاقة «جاهز للتسليم» لكل عميل (موجودة ✅) |
| الحركة | حركة تسليم من أمانة العميل → **صفر أمانة** (خروج من التتبع) |
| التوقيع | سند تسليم مطبوع بالتوقيع والوزن |

### الخطوة 5 — التسوية والكشف
- كشف حساب أمانة لكل عميل: استلامات / طحنات / تسليمات / رصيد قائم (الموجود `customer-statement` يجب توسيعه بعرض الفاقد ورصيد الأكياس).
- **التسوية القسرية:** لا يُغلق العمل قبل أن يصبح رصيد الأمانة = 0 (حبوب 0 ونواتج 0) — أو يُوثَّق فرق متبقٍ بأمر تسوية موقّع.

### الخطوة 6 — التتبع (Traceability)
سلسلة تتبع كاملة عبر `source_type/source_id`:
```
سند استلام أمانة (AST-12)
   └── عملية طحن (MIL-34)  ← استهلك X كجم من أمانة AST-12
         └── نواتج M كجم تُعاد إلى أمانة AST-12
               └── سند تسليم (DLV-8) ← خرجت من الأمانة
   └── فاتورة أجور (SRV-56) ← مرتبطة بـ MIL-34
```
**الخطأ الحالي:** حركات الأمانة ليست كلها موثقة المصدر بهذه السلسلة (الفاقد يظهر كمبلغ فقط)، فلا يمكن الإجابة على سؤال «هذا الكيس جاء من أي استلام؟».

# القسم الثاني: التصنيع الداخلي = **تحويل** وليس إنتاج

## 2.1 الخطأ البنيوي الحالي (الأخطر محاسبياً)

`milling/manufacture.tsx` يطبق **نظام تصنيع كامل**:
> «يتم خصم القمح من المخزون بتكلفته الفعلية، وتُوزع التكلفة بالكامل على النواتج بحسب
> نسبة القيمة السوقية لكل منتج، مع إثبات الفاقد التشغيلي في دفتر الأستاذ (حـ/5921)»

هذا نموذج **joint-cost allocation** (توزيع التكلفة المشتركة حسب القيمة السوقية النسبية).
**هذا لا يناسب هذا النظام** لأنه:
1. يتطلب قيماً سوقية حية للنواتج (في نظام مبسط هذه أرقام غير موثوقة).
2. يفرض قيد توزيع معقداً كل عملية، والفروق تتراكم في حساب «فاقد تشغيلي» مصطنع.
3. **المصروفات الحقيقية** (أجور العمال، الغاز، أكياس فارغة، مشغّل) تُسجَّل في وحدة
   المصروفات المنفصلة أصلاً — فلماذا يُعاد اختراع توزيعها داخل عملية التصنيع؟

## 2.2 النموذج الصحيح: تحويل مبسط بالتكلفة الدفترية

```
عملية تحويل (Conversion Order):
  مدخلات:  قمح 1000 كجم @ تكلفة فعليّة من طبقات المخزون = 500,000
  نواتج:   دقيق 780 كجم + نخالة 200 كجم  (مجموع = 980 + فاقد 20)
  
القاعدة:
  تكلفة النواتج = تكلفة المدخلات المخصومة (بدون أي إضافات)
  توزيعها على النواتج: حسب **الوزن** أو حسب نسبة قياسية ثابتة (اختيار واحد معتمد)
  الفاقد: يبقى ضمن تكلفة النواتج (تُحمّل النواتج كلها الناتج الصافي)
  المصروفات: سندات مصروفات عادية مستقلة — لا تدخل تكلفة الصنف
```

| البند | النظام الحالي (خطأ) | النظام الصحيح |
|---|---|---|
| توزيع التكلفة | نسبة القيمة السوقية | نسبة الوزن (أو نسب قياسية) |
| الفاقد | حساب 5921 قيد تصنيعي | ضمن تكلفة النواتج، ويُظهر كبيان معلوماتي فقط |
| أجور ومستلزمات | لا تُدخل أصلاً أو توزيع مضاعف | **سندات مصروفات** في دفتر المصروفات |
| القيد | قيد توزيع معقد متعدد الأطراف | حركتا مخزون فقط: خصم مدخلات @ تكلفة طبقة، إضافة نواتج بنفس الإجمالي موزعاً بالوزن |
| أستاذ عام | قيد 5921 | لا قيد إضافي — الحركة واحدة توازن ذاتياً |

## 2.3 حساب التكلفة في التحويل (مثال رقمي)

```
مدخلات: قمح 1000 كجم، تكلفة طبقة فعليّة 500 ر.س/كجم → 500,000
نواتج:  دقيق 780 كجم، نخالة 200 كجم، فاقد 20 كجم
        إجمالي نواتج = 980 كجم
        تكلفة/كجم = 500,000 / 980 = 510.20
        دقيق: 780 × 510.20 = 397,960
        نخالة: 200 × 510.20 = 102,040  (المجموع = 500,000 ✅)
```
الفرق الوحيد المسموح بين القيمة الدفترية والسعر البيعي هو **هامش البيع الطبيعي**،
لا قيود توزيع.

# القسم الثالث: الشراء والتوريد (Purchases)

| العنصر | التفصيل |
|---|---|
| الفاتورة | مورّد + مستودع + أصناف (كجم أو أكياس بحسب فهرس العبوة) |
| التكلفة | تكلفة الشراء + الشحن/التنزيل **كبنود تكلفة إضافية** (landed cost) توزَّع بالوزن |
| الحركة | `post_stock_delta(kind=RECEIPT)` → تقييم طبقة جديدة في `apply_cost_movement` |
| الذمم | رصيد المورّد + دفتر أستاذ الموردين |
| **الخطأ الحالي** | بنود تكلفة إضافية (شحن/تنزيل) غير موجودة كتوزيع، تُدخل كأسطر فاتورة عادية فتُشوّه سعر الوحدة |
| **الصحيح** | حقل «مصاريف شحن مشتركة» في فاتورة الشراء توزَّع آلياً بالوزن على أصناف الفاتورة قبل التقييم |

# القسم الرابع: التحويل بين المستودعات (Transfers)

| العنصر | التفصيل |
|---|---|
| العملية | أمر تحويل: مستودع مصدر → مستودع وجهة |
| الحركة | `TRANSFER_OUT` + `TRANSFER_IN` في نفس المعاملة، نفس التكلفة تنتقل دون إعادة تقييم |
| الفحص | رصيد المصدر ≥ الكمية (يمنع المحرك)، وعدم تحويل إلى مستودع غير مفعّل |
| **الخطأ الحالي** | لا يوجد فحص أن المستودعين مختلفين في الواجهة (تحويل ذاتي ممكن)، ولا سجل تحويلات بفلترة من/إلى |
| **الصحيح** | تحقق واجهة (مصدر ≠ وجهة) + سجل تحويلات كامل في نفس الشاشة |

# القسم الخامس: المصروفات (Expenses)

| العنصر | التفصيل |
|---|---|
| السند | سند صرف مصروف: بند، مبلغ، وسيلة دفع (صندوق/بنك)، مرجع |
| **دورها في التصنيع** | أجور الطحن الداخلي، الغاز، أكياس فارغة، صيانة — كلها **مصروفات فترة** وليست تكلفة أصناف |
| الربط المحاسبي | تُرحَّل لدفتر اليومية فوراً (النظام الحالي يفعلها ✅) |
| **الخطأ الحالي** | لا تصنيف «مصروف تشغيل مرتبط بقسم الطحن» يسمح بقراءة تكاليف الطحن الشهرية في تقرير واحد |
| **الصحيح** | كتالوج بنود مصروفات (أجور/غاز/أكياس/صيانة/نقل) + تقرير «مصروفات الطحن» شهري |

# القسم السادس: البيع والمخزون والتسعير

## 6.1 بنية المنتجات الصحيحة (صنف + فهارس عبوة)

**البنية الحالية (خطأ):** كل حجم كيس = منتج مستقل بـ `package_weight_kg` على المنتج.
**البنية الصحيحة:**

```
الصنف Item: دقيق أبيض (price_per_kg = 280)
   ├── فهرس عبوة 50 كجم  → سعر مشتق 14,000 | باركود خاص
   ├── فهرس عبوة 25 كجم  → سعر مشتق 7,000   | باركود خاص
   └── فهرس عبوة 10 كجم  → سعر مشتق 2,800   | باركود خاص

المخزون داخلياً: كجم فقط (طبقات تكلفة FWA)
الفاتورة: 3 كيس 50 كجم → 3 × 14,000 — والمحرك يخصم 150 كجم داخلياً
```

| الميزة | الأثر |
|---|---|
| تعديل سعر الكجم مرة | يتحدث سعر كل العبوات فوراً |
| تقرير «مبيعات الدقيق الأبيض» | صنف واحد بأحجام، لا تشرذم |
| جدول `product_packages` | `product_id, size_kg, barcode, price_override, is_default, is_active` |
| ترحيل | سكربت يحول كل منتج بـ `package_weight_kg` إلى صنف + فهرس عبوة واحد |

## 6.2 البيع (POS + فواتير)

| العنصر | التفصيل |
|---|---|
| الوحدة في السلة | العبوة (الاسم يظهر: «دقيق أبيض — كيس 50 كجم») |
| المخزون | خصم كجم عبر المحرك فقط — منع أي كتابة مباشرة على `stock_movements` (المشغّل موجود ✅) |
| التكلفة | من الطبقة الفعلية `sale_line_unit_cost` (✅ موجود) |
| الخصم والضريبة | على مستوى الفاتورة |
| **الخطأ الحالي** | تكرار الأصناف بالأحجام (E-6.1)، وعدم ظهور سعة العبوة في بطاقات POS والشبكة (E-6.2) |
| **الصحيح** | اختيار «صنف ← عبوة» في POS، وعمود «سعة» في الشبكة والبطاقات |

## 6.3 المخزون

| القاعدة | التفصيل |
|---|---|
| الوحدة الداخلية | كجم للكل (الحبوب والدقيق والنخالة) |
| المحرك الوحيد | `post_stock_delta` — المفتاح `app.stock_engine` (✅ مطبق) |
| الطبقات | `apply_cost_movement` + `resolve_unit_cost` (✅) |
| الجرد والتسوية | عبر شاشة التسوية فقط، بسبب إلزامي |
| حدود | حد أدنى بالكجم لكل صنف (لا لكل عبوة) |

# القسم السابع: التكامل مع النظام المحاسبي

| الجانب | القاعدة |
|---|---|
| فاتورة بيع | إيراد + ذمم/صندوق + COGS/مخزون (✅ `post_sales_invoice`) |
| فاتورة أجور طحن | إيراد خدمة + ذمم/صندوق — **بلا COGS** |
| شراء | مخزون + ذمم موردين + بنود تكلفة موزعة |
| تحويل | حركات مخزون فقط، **لا قيود** (نفس المعاملة توازن ذاتياً) |
| تحويل تصنيعي | حركتا مخزون فقط، **لا قيد توزيع، لا 5921** |
| مصروفات | سند صرف → مصروف + صندوق/بنك فوراً |
| الفاقد (خدمة) | بيان معلوماتي على عملية الطحن — لا قيد |
| الفاقد (تحويل) | ضمن تكلفة النواتج — لا قيد منفصل |

# القسم الثامن: العملاء والذمم

| العنصر | التفصيل |
|---|---|
| العميل النقدي | حساب نظامي محمي لا يحمل ذمة (✅ مفروض بالدوال) |
| حد الائتمان | يفحصه المحرك (`customer_credit_limit_allows` ✅) |
| الذمة | رصيد العميل + دفتر أستاذ مرجعي (✅) |
| الأمانات | **منفصلة عن الذمة المالية** — رصيد أمانة مادي لا دين مالي، ويُعرض في كشف أمانات منفصل |
| **الخطأ الحالي** | خلط محتمل في العرض: أمانات وسندات في شاشة واحدة يوحي بأن المبلغ دين |
| **الصحيح** | شاشة «أمانات» (أوزان) منفصلة تماماً عن شاشة «ذمم» (أموال) |

## 📌 خلاصة تنفيذية

1. **طحن الغير:** حبوب = أمانة، النواتج = أمانة، الإيراد = أجور فقط، الفاتورة بعد الطحن الفعلي، لا تسعير للنواتج، سجلات كاملة في كل شاشة.
2. **التصنيع الداخلي:** تحويل مخزون بنفس التكلفة موزعاً بالوزن، المصروفات = مصروفات، **إلغاء التوزيع النسبي و5921**.
3. **المنتجات:** صنف واحد بسعر كجم + فهارس عبوة، لا تكرار أصناف بالأحجام.
4. **المخزون:** كجم داخلياً في كل مكان، محرك حركة وحيد، طبقات تكلفة، لا كتابة مباشرة.
5. **الرسائل:** توست واحد موثق بالعربية عبر طبقة الترجمة، والسندات من أزرار صريحة.
