# نشر Vortex ERP على Docker

هذا الإعداد ينشر **تطبيق Vortex ERP فقط** خلف Caddy مع HTTPS تلقائي، ويعيد تشغيل الحاويات بعد خروجها أو إعادة تشغيل Docker باستخدام `restart: unless-stopped`. لا يشغّل قاعدة بيانات Supabase ولا يغيّر إعداد Supabase المحلي المستخدم للتطوير.

## المتطلبات

- خادم Linux عليه Docker Engine وDocker Compose Plugin.
- اسم نطاق يشير سجله `A`/`AAAA` إلى الخادم، مع السماح بالوصول إلى المنفذين TCP `80` و`443` وUDP `443`.
- مشروع Supabase إنتاجي مستقل، مُدار أو مستضاف ذاتياً، ومهيأ بعنوان ومفاتيح إنتاج.

## الإعداد والتشغيل

1. انسخ المستودع إلى الخادم، ثم أنشئ ملف الإعداد من النموذج:

   ```sh
   cp deploy/app.production.env.example deploy/.env.production
   chmod 600 deploy/.env.production
   ```

2. عدّل `deploy/.env.production` وضع عنوان Supabase ومفتاح النشر العام ومفتاح `service_role` واسم النطاق. استخدم أسراراً خاصة ببيئة الإنتاج، ولا تضع المفتاح السري في قيمة `VITE_*`.

3. شغّل من مجلد المستودع:

   ```sh
   docker compose --env-file deploy/.env.production -f deploy/compose.production.yaml up -d --build
   ```

4. راجع حالة الحاويات والسجلات:

   ```sh
   docker compose --env-file deploy/.env.production -f deploy/compose.production.yaml ps
   docker compose --env-file deploy/.env.production -f deploy/compose.production.yaml logs -f app proxy
   ```

لتحديث إصدار التطبيق، اجلب التغيير المقصود ثم أعد أمر `up -d --build`. لا تحذف أحجام Caddy أثناء التحديث حتى تبقى بيانات شهادات TLS محفوظة.

## حدود الأمان والتشغيل

- `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` إعدادان عامان يدمجان في ملفات المتصفح؛ الحماية تعتمد على RLS وسياسات قاعدة البيانات.
- `SUPABASE_SERVICE_ROLE_KEY` سر خادمي يتجاوز RLS. خزّنه في ملف الخادم بصلاحيات مقيدة أو استخدم مدير أسرار مناسباً، ودوّره عند انكشافه. لا ترفعه إلى Git ولا تضعه في build args.
- لا تفتح المنفذ `3000` للإنترنت. ينشر Caddy المنفذين `80/443` ويوجه الطلبات إلى التطبيق داخل شبكة Compose الخاصة.
- `unless-stopped` يعيد تشغيل الحاوية بعد التوقف، لكنه لا يوفر مراقبة خارجية أو نسخاً احتياطية أو تحديثات أمنية. اضبط مراقبة وتنبيهات ونسخاً احتياطية لقاعدة Supabase على حدة.
- هذا الملف لا يضمّن Supabase. عند الاستضافة الذاتية، استخدم حزمة Docker الرسمية لـ Supabase وإعدادها الإنتاجي بشكل مستقل، مع شبكة خاصة واتصال TLS وسياسة نسخ احتياطي واستعادة مجرّبة. لا تستخدم `supabase start` كخدمة إنتاج عامة.
- نجاح بناء صورة التطبيق وإقلاعها لا يثبت جاهزية النظام التجارية أو المالية للإنتاج؛ يلزم التحقق من البناء، وتوافق الترحيلات والبيانات، واختبارات قبول الأعمال، وخطة الاستعادة قبل تشغيل بيانات الشركات.

## تنبيه التحقق

الإعداد هنا نقطة نشر قابلة للمراجعة، ولم يُنفذ عليه `docker compose config` أو بناء صورة أو تشغيل حاويات في هذه الخطوة. يجب تنفيذ هذه التحققات على بيئة تجهيز قبل اعتماد النشر الفعلي.
