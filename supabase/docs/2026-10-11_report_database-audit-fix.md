## 2. الخطأ المانع: `legacy_id` فارغ

### 2.1 العَرَض

```
Seeding data from supabase/seeds/01_system/08_payment_methods.sql...
failed to send batch: ERROR: null value in column "legacy_id" of relation
"payment_methods" violates not-null constraint (SQLSTATE 23502)
```

### 2.2 السبب الجذري

في الجلسة السابقة حُذف `ALTER COLUMN legacy_id SET DEFAULT 'cash'` من الترحيل 16 —
وهو القرار الصحيح (كان يُخفي بنكًا كنقد)، لكنه كشف أن **البذرة لا تكتب `legacy_id`
صراحةً**، فكانت تعتمد على الافتراضي المحذوف. والعمود `NOT NULL`، فالـ`INSERT` رُفض.

هذا مثال عملي على أن إزالة الافتراضي **تعمل كما هو مقصود**: «أغفلتُ الحقل» تفشل
بصوت عالٍ بدل أن تُسجّل بنكًا كصندوق.

### 2.3 الإصلاح

البذرة `08_payment_methods.sql` صارت تُمرّر `legacy_id` في كل صف، وهو **القيمة
المخزّنة الشرعية** المشتقة من عائلة الحساب:

| الطريقة             | `legacy_id`     | لماذا                                  |
| ------------------- | --------------- | -------------------------------------- |
| `cash`              | `cash`          | نقدي                                   |
| `credit`            | `credit`        | آجل                                    |
| `bank_transfer`     | `bank_transfer` | بنك عام                                |
| `kuraimi_bank`      | `bank_transfer` | بنك — يشترك في القيمة التاريخية العامة |
| `yemen_kuwait_bank` | `bank_transfer` | بنك                                    |
| `card`              | `card`          | شبكة                                   |
| `cheque`            | `cheque`        | شيك                                    |
| المحافظ الخمس       | `mobile_money`  | محفظة                                  |
| `split`             | `split`         | مجزّأ                                  |

وأُضيف `legacy_id = EXCLUDED.legacy_id` إلى قسم `ON CONFLICT DO UPDATE`.

## 3. أخطاء البيانات: المؤسسات المالية

### 3.1 «جيب» ليست تابعة لبنك الكريمي — تصحيح

**ما كان مكتوبًا:**

```sql
('jaib', 'جيب', 'Jaib Wallet', 'wallet', ..., 'محفظة جيب التابعة لبنك الكريمي.')
```

**الحقيقة:** «جيب» (Jaib) محفظة رقمية مستقلة طوّرتها **شركة الأهدل المالية**
(AHD FINANCIAL). لا صلة لها ببنك الكريمي. وصفها كفرع للكريمي **خطأ في بيانات
مرجعية** يُضلّل المستخدم ويخلط مؤسستين مختلفتين محاسبيًا.

**الإصلاح:**

```sql
('jaib', 'جيب', 'Jaib', 'wallet', ..., 'محفظة إلكترونية مستقلة (شركة الأهدل المالية). ليست تابعة لبنك الكريمي.')
```

الاسم الإنجليزي صار `Jaib` (لا `Jaib Wallet`)، والتوضيح صريح في `notes`.

### 3.2 ملاحظة على بقية المؤسسات

راجعتُ المؤسسات الست في الكتالوج، وهذا تصنيفها الصحيح:

| المعرّف             | الاسم              | النوع      | الكيان                              |
| ------------------- | ------------------ | ---------- | ----------------------------------- |
| `cash`              | نقداً              | نقد        | —                                   |
| `credit`            | آجل                | ذمة        | —                                   |
| `bank_transfer`     | تحويل بنكي         | بنك عام    | —                                   |
| `kuraimi_bank`      | بنك الكريمي        | بنك        | بنك الكريمي الإسلامي للتمويل الأصغر |
| `yemen_kuwait_bank` | بنك اليمن الدولي   | بنك        | Yemen International Bank            |
| `jawali`            | جوالي              | محفظة      | يمن موبايل                          |
| `jaib`              | جيب                | محفظة      | الأهدل المالية (AHD)                |
| `floosak`           | فلوسك              | محفظة      | Quality Connect                     |

## 4. خطأ محاسبي: المحافظ بلا حسابات

### 4.1 العَرَض

كل المحافظ كانت تُرحَّل إلى `1111` (البنك) عبر `ledger_kind = 'WALLET'`. فسند قبض
بجوالي، وبجيب، وبفلوسك — **كلها في حساب واحد**. النتيجة:

- لا يمكن معرفة كم في محفظة جوالي وحدها.
- لا يمكن مطابقة كشف جوالي مع دفتر الأستاذ.

وهذا خلل محاسبي حقيقي، لا شكلي: **مطابقة الحساب البنكي/المحفظي مستحيلة**.

### 4.2 الإصلاح

أُضيفت خمسة حسابات في دليل الحسابات (نطاق `113x` = نقدية مكافئة)، وأُسندت لكل
محفظة:

| الكود  | الحساب                 | المحفظة        |
| ------ | ---------------------- | -------------- |
| `1131` | محفظة — جوالي          | `jawali`       |
| `1132` | محفظة — الأهدل المالية | `jaib`         |
| `1133` | محفظة — فلوسك          | `floosak`      |
| `1134` | محفظة — ون كاش         | `one_cash`     |
| `1139` | محفظة إلكترونية — أخرى | `mobile_money` |

وكذلك البنوك:

| الكود  | الحساب                | الطريقة                                           |
| ------ | --------------------- | ------------------------------------------------- |
| `1111` | البنك — الحساب الأول  | `bank_transfer`, `kuraimi_bank`, `card`, `cheque` |
| `1121` | البنك — الحساب الثالث | `yemen_kuwait_bank`                               |
| `1101` | النقدية بالصندوق      | `cash`, `split`                                   |
| `1211` | ذمم العملاء           | `credit`                                          |
| `NULL` | —                     | `credit` لا يُحصَّل شيئًا فلا سطر نقدي            |

> **الأسماء محايدة عمدًا** («محفظة — جوالي») لأن منشأة قد لا تستخدم محفظة معيّنة.
> المالك يعيد التسمية من شاشة دليل الحسابات. الأكواد ثابتة (عقد مع محرّك الترحيل).

**النتيجة:** صفر محفظة بلا حساب (`wallets_no_acct = 0`).

## 5. تعارضات بين الملفات

هذا ما طلبتَ التركيز عليه: «هل في تعارض بين المجريشن والبيانات؟». وُجد نوعان، وكلاهما
يخالف `MIGRATIONS_RULES.md` (R-13/R-14: كل دالة تُعرَّف مرة واحدة).

### 5.1 دوال مُعرَّفة في ملفين (7 دوال)

| الدالة                        | كانت في     | صارت في    | السبب                         |
| ----------------------------- | ----------- | ---------- | ----------------------------- |
| `post_sales_invoice`          | 08 **و** 16 | **16** فقط | فرع الحساب يحتاج كتالوج الدفع |
| `post_purchase_invoice`       | 08 **و** 16 | **16** فقط | نفس السبب                     |
| `next_invoice_number`         | 06 **و** 14 | **14** فقط | المحرّك الجديد                |
| `next_sales_return_number`    | 06 **و** 14 | **14** فقط | المحرّك الجديد                |
| `next_purchase_number`        | 07 **و** 14 | **14** فقط | المحرّك الجديد                |
| `next_purchase_return_number` | 07 **و** 14 | **14** فقط | المحرّك الجديد                |
| `next_transfer_number`        | 05 **و** 14 | **14** فقط | المحرّك الجديد                |

**لماذا هذا خطير؟** لأن النسخة السارية كانت «الأخيرة زمنيًا» فقط. فمن يعدّل `08`
ظنًّا أنه يعدّل الترحيل، لا يرى أي أثر — لأن `16` يُعيد تعريف الدالة بعده. وقد
كُتب في `08` تصميم ترقيم **مختلف** (يقرأ `company_settings`) عن تصميم `14`
(يقرأ `document_numbering`) — تصميمان متضاربان لنفس الوظيفة.

**الإصلاح:** حُذفت النسخ الأقدم، وكل دالة **تُعرَّف مرة واحدة** في ملفها الصحيح،
مع ملاحظة صريحة في مكان الحذف تشرح أين انتقلت ولماذا. التوقيعات لم تتغير، فلا
ينكسر أي مستدعٍ.

### 5.2 `GRANT` لدوال غير موجودة (خطأ توقيت)

`13_foreign_keys_and_grants.sql` كان يمنح صلاحية تنفيذ على 7 دوال **قبل** أن
تُعرَّف (لأن `13` يسبق `14`–`16`). كان يعمل قديمًا لأن النسخ القديمة في 05–08
كانت تُعرّفها. بعد 5.1، صارت الدوال تُعرَّف لاحقًا، فلو بقيت المنح في `13`
لَفشل `db reset` بـ«function does not exist».

**الإصلاح:** نُقلت المنح إلى جانب التعريفات في `14` و`16`.

### 5.3 نتائج الفحص

```
فحص التكرار عبر كل ملفات الترحيل:
  → NO CROSS-FILE DUPLICATES
```

## 6. شعارات البنوك والمحافظ

### 6.1 ما أُنشئ

مجلد جديد `public/payment-icons/` يحوي:

- **10 ملفات SVG**: `cash`, `credit`, `bank-transfer`, `kuraimi`, `bank`,
  `mobile-money`, `wallet`, `card`, `split`, `generic`.
- **`manifest.json`**: سجل المفتاح → الملف.
- **`README.md`**: الشرح والملكية القانونية.

وملف ربط في الواجهة: **`src/lib/payments/payment-icons.ts`**، ودالّتان:

```ts
paymentIconUrl(iconKey); // مفتاح الكتالوج → مسار الملف
paymentIconUrlFromStoredValue(stored); // قيمة الـENUM القديمة → مسار الملف
```

### 6.2 السلسلة — بلا تكرار

```
public.payment_methods.icon_key   ('kuraimi')
    │
    ▼  manifest.json
    │
    ▼  paymentIconUrl()
    │
    ▼  /payment-icons/kuraimi.svg
```

مفتاح مجهول لا يكسر الشاشة — يعود إلى `generic.svg`.

### 6.3 ⚠️ ملاحظة قانونية مهمة

هذه الأيقونات **رسوم رمزية أنشأناها** (محفظة، بطاقة، درع…) بألوان النظام،
**وليست الشعارات الرسمية** للمؤسسات. السبب: الشعار الرسمي علامة تجارية مملوكة،
ووضع نسخة غير مرخّصة في منتج لعميل قد يُعرّضه لمخالفة. ولم أجد نسخًا رسمية بصيغة
SVG متاحة للاستخدام من مصادر موثوقة.

**البنية جاهزة للاستبدال:** ضع الملف الرسمي بنفس الاسم (`kuraimi.svg` …) فيُعرض
تلقائيًا في كل الشاشات — بلا تعديل كود ولا قاعدة بيانات. التفاصيل في
`public/payment-icons/README.md`.
