# الترحيلات النشطة

المسار النشط لبناء **قاعدة جديدة** هو ملفات SQL هنا، وهي خط الأساس المختصر
المعاد بناؤه من الحالة النهائية للمخطط. كل جدول يُعرّف مرة واحدة في ملف مجاله؛
لا تُستخدم ترقيعات التاريخ القديم لبناء قاعدة جديدة.

- تفاصيل الملفات وقرارات البناء: [`../migrations_baseline/README.md`](../migrations_baseline/README.md)
- بيانات النظام المنفصلة عن المخطط: [`../seeds/README.md`](../seeds/README.md)
- التاريخ السابق محفوظ كما هو في [`../migrations_legacy/`](../migrations_legacy/)

## تحذير للبيئات القائمة

هذه المجموعة تعيد تأسيس سجل الترحيلات. لا تطبقها على قاعدة قائمة أو سحابية، ولا
تستخدم `db reset` أو تحاول مزامنة سجلها تلقائيًا. أي نقل لبيئة قائمة يحتاج خطة
انتقال ومطابقة مستقلة. سكربت `npm run db:selfhosted:push:local` محصور بقاعدة
Docker المحلية على `127.0.0.1:5433` ويطلب تأكيدًا صريحًا.

## حالة إعادة بناء السحابة

في 2026-11-06 أُعيد بناء المشروع المرتبط `kwzqvgdyadylwnvjghqn` من هذه المجموعة
بعد طلب صريح بحذف بياناته. نجح سجل `001..015` وبذور النظام فقط؛ لا توجد حسابات
`auth.users` أو بيانات شركة/عرض. لم تُنشأ نسخة احتياطية بناءً على طلب المستخدم.
إعادة ضبط أي قاعدة قائمة لاحقًا تتطلب طلبًا صريحًا مستقلًا؛ التغييرات المستقبلية
تُضاف كترحيلات أمامية.

## الترحيلات الأمامية بعد إعادة البناء

- `018_allow_negative_sales_create_sale_guard.sql`: يوحّد الحارس المبكر في
  `create_sale` مع سياسة `allow_negative_sales`. يسمح فقط لفاتورة البيع

  لمسارات الإنتاج والتحويل والجرد.
