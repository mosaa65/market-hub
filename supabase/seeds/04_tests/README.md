# 04_tests — مثبتات الاختبارات

هذا المجلد لـ **مثبتات الاختبارات الآلية** (Test Fixtures): بيانات ثابتة تجعل
نتيجة الاختبار قابلة للتكرار. يُشغَّل **من الاختبارات فقط**، ولا يُشغَّل على
قاعدة عميل أبدًا.

## القاعدة الحاكمة: نتيجة قابلة للتكرار

الاختبار الذي يعتمد على `now()` أو على UUID عشوائي **ليس اختبارًا**. ينجح اليوم
ويفشل غدًا، أو ينجح على جهازك ويفشل في السحابة.

```sql
-- ❌ لا يصح
INSERT INTO public.sales_invoices (id, invoice_number, created_at)
VALUES (gen_random_uuid(), 'INV-' || floor(random()*1000), now());

-- ✅ يصح
INSERT INTO public.sales_invoices (id, invoice_number, created_at)
VALUES ('11111111-1111-1111-1111-111111111111',
        'TEST-INV-0001',
        '2026-01-01T00:00:00Z'::timestamptz);
```

المعرّف الثابت مقبول **هنا فقط**، بخلاف ملفات العيّنات التي يُمنع فيها قطعًا.

---

## قواعد المثبّت

### 1. ثابت (Idempotent)
`ON CONFLICT` على المفتاح، ليعمل تشغيل الاختبارات مرتين بلا خطأ.

### 2. ينظّف ما أنشأ
كل مثبّت يبدأ بحذف ما سيُنشئه، ليستقلّ عن ترتيب تشغيل الاختبارات:

```sql
DELETE FROM public.sales_invoice_items WHERE invoice_id = '111...';
DELETE FROM public.sales_invoices      WHERE id         = '111...';
-- ثم الإدخال
```

### 3. لا يمسّ بيانات النظام
**ممنوع** حذف أو تعديل صفوف من `01_system` — الحسابات أو الوحدات أو التصنيفات.
مثبّت يحذف حسابًا يكسر كل اختبار آخر في المجموعة.

### 4. معزول عن بيانات العرض
لا يعتمد على وجود `sample-mill.sql`. الاختبار يبني ما يحتاجه بنفسه.

## التشغيل

من داخل الاختبار، أو يدويًا للتحضير:

```bash
psql "$DATABASE_URL" -f supabase/seeds/04_tests/fixtures.sql
```
